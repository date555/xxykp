# 向咸鱼开炮：静态网站部署

当前游戏可以部署到 Cloudflare Pages 或 GitHub Pages。玩家通过浏览器打开网站，加载资源后就能布阵、出征，不需要安装 Node.js，也不需要连接原游戏账号。`server.mjs` 只是本地预览服务器，不是线上必需的后端。

## 已准备好的发布文件

在本游戏目录执行：

```powershell
npm run build
```

也可以直接执行 `node tools/build-site.mjs`，无需安装依赖。生成的 `dist/` 是完整静态网站；它包含入口页面、代码、原版素材、动画预览和运行库许可证，不包含开发文档、本地服务、测试及素材提取脚本。

本次生成 2176 个文件，40,760,515 字节（约 40.76 MB / 38.87 MiB），最大单文件约 1.44 MiB。发布时上传 `dist` 内的文件，`index.html` 应位于站点根目录，不要额外套一层 `dist`。完整构建结果见 `deployment-build.json`。

## Cloudflare Pages

### 方式一：连接 Git 仓库

1. 将“向咸鱼开炮”文件夹内的内容放进独立仓库，仓库根目录应能看到 `package.json`、`index.html`、`tools/` 和 `assets/`，包括隐藏的 `.github/`。不要上传整个“咸鱼代码分析”工作区。
2. 在 Cloudflare Pages 中连接这个仓库。
3. 框架预设选 None，构建命令填写 `node tools/build-site.mjs`，输出目录填写 `dist`。如果游戏就是仓库根目录，根目录设置留空。Node.js 版本可设为 24。
4. 部署完成后使用平台给出的 `pages.dev` 地址，也可绑定自己的域名。之后推送代码可自动更新。

### 方式二：从本地发布

在本游戏目录运行以下命令，按提示登录、选择账户和创建项目：

```powershell
npm run build
npx wrangler login
npx wrangler pages deploy dist --project-name xiang-xianyu-kaipao --branch main
```

项目名称可按自己的账户情况调整，最终地址以 Cloudflare 返回的结果为准。这里记录的是部署步骤，本次尚未执行登录或发布。

Cloudflare Pages 免费方案支持最多 20,000 个文件、单文件 25 MiB；当前包符合这些限制。网页拖拽上传只有 1,000 个文件上限，因此本项目需要 Git 连接或 Wrangler 上传。Direct Upload 项目以后不能直接切换成 Git 集成项目，若希望持续自动更新，优先使用方式一。[平台限制](https://developers.cloudflare.com/pages/platform/limits/) · [直接上传说明](https://developers.cloudflare.com/pages/get-started/direct-upload/)

## GitHub Pages

1. 同样将本游戏文件夹内容作为独立仓库根目录，保留 `.github/workflows/deploy-pages.yml`，推荐主分支名 `main`。
2. 打开仓库 Settings → Pages，把 Source 选为 GitHub Actions。
3. 在 Actions 中运行 `Deploy game to GitHub Pages`；以后推送 `main` 也会触发。若主分支不是 `main`，同步修改工作流中的分支名。
4. 成功后打开 Pages 提供的地址，通常是 `https://你的用户名.github.io/仓库名/`。

工作流会整理 `dist` 再上传，已包含 `.nojekyll`。页面、CSS、模块和动画资源使用相对路径，动画预览的“返回游戏”也已经适配仓库子目录。工作流配置已准备，但尚未在 GitHub 上执行。

GitHub Pages 已发布站点上限为 1 GB，月流量软上限为 100 GB；当前包大小符合要求。GitHub Free 可使用公开仓库的 Pages，私有仓库是否可用取决于账户方案。[官方限制](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits) · [Actions 部署说明](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)

## 存档和在线运行方式

- 每位玩家的进度保存在自己的浏览器中；当前是单机玩法，没有账户云存档、联机同步或共享排行榜。
- 同一网址、同一浏览器中刷新或更新网站会继续读取存档。改游戏名称和本地目录不会清空原 `127.0.0.1:4178` 的进度，存储键继续兼容旧版。
- 本地地址、Cloudflare 域名和 GitHub 域名属于不同地址，存档不会自动搬过去。可先在设置中导出，然后到新网站导入；更换设备同理。
- 资源按当前阵容和章节加载，发布包的总体积不等于每次进入游戏必须下载的流量。

以上平台规则核对于 2026-10-26。本次交付为本地可部署包及配置，不包含已经上线的公网网址。
